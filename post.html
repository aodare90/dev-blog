Why my flex items refused to shrink

A long link kept breaking my card layout. The fix was one line, and the reason behind it taught me how flexbox decides sizes.

I was building a small profile card: an avatar on the left and some text on the right. It looked fine until I pasted in a real website address. The text column refused to get narrower, and the whole card pushed past the edge of the screen on my phone.

My first guess was that I needed flex-shrink: 1. That is already the default, so adding it changed nothing.

What was actually happening

Flex items have a hidden rule: by default they will not shrink smaller than their content. In CSS terms, a flex item's min-width is auto, and for a flex item auto means “as wide as the longest thing inside that can't wrap”. A long URL has no spaces, so it can't wrap, and the column can't shrink.

Setting min-width: 0 removes that floor, so the column can be as narrow as the card needs. On its own the URL would then spill out of the column, which is why the second line, overflow-wrap: anywhere, lets it break onto a new line.

How I found it

I opened DevTools, selected the text column, and looked at its computed width. It was wider than the card. Hovering the URL showed it was exactly the same width as the column, which made it clear the content was setting the size, not the layout.

Flex items won't shrink smaller than their content unless you give them min-width: 0. Grid items behave the same way, so a column defined as 1fr has the same problem and the same fix: use minmax(0, 1fr).
